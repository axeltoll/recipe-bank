# Working through the queue

Use this procedure with [RECIPE-AGENT.md](RECIPE-AGENT.md). Stop the dashboard (`Ctrl+C` in its terminal) before the helper writes `data/queue.json`: the helper serializes its own instances but does not share the server's in-memory write lock. Do not run several analysis agents against the same queue.

1. `node scripts/queue.mjs next` prints the oldest `queued` entry as JSON, or `null` if there is none. Oldest means earliest valid `addedAt`; ties preserve file order and missing/invalid dates sort last. This is read-only and does not claim the entry. Check whether the video already has a recipe before analyzing it.
2. `node scripts/queue.mjs mark <id> analyzing` claims a queued entry. Follow the shared analysis skill. A direct video link needs no queue entry; if it matches an existing entry, use that entry. For an unresolved TikTok short link, replace the entry's `video` with the verified canonical platform, ID and URL from captured metadata before completion, so it matches the resulting recipe; run validation after that edit.
3. When analysis is impossible, use `node scripts/queue.mjs mark <id> failed "Captions unavailable and no usable source material"`. Use a concise factual reason, without captured source text or private paths. The helper records `failureReason` and keeps the entry. A partial but useful recipe follows the shared contract instead.
4. After the finished recipe passes `npm run validate`, use `node scripts/queue.mjs mark <id> done`. This removes the entry only if a matching recipe exists and passes the contract. It does not create a `done` queue status. Run validation again and the shared done checklist.
5. A deliberate retry uses `node scripts/queue.mjs mark <id> queued` on a failed entry; it clears the old failure reason. The helper refuses other transitions, unknown IDs, malformed JSON, duplicate queue IDs and completion without a valid matching recipe. An interrupted `analyzing` entry can be marked failed with an interruption reason, then explicitly requeued.

The helper writes through an exclusive `.agent.tmp` file and renames it over the queue. If a process was killed and left this file behind, first make sure no helper is running, inspect it for recoverable work and remove the stale temporary file before retrying. A detected concurrent queue edit aborts the write. Restart the dashboard once queue maintenance is finished.
