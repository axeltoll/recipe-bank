Self-hosting guide

Run Recipe Bank on your own machine.

Everything below describes the repository as it is today. Where something is only planned, it says so.

What you need

  • Node.js 22 or newer.
  • Git, to clone the repository.
  • A current browser.

There is no install step. Recipe Bank has no dependencies, so there is nothing for npm install to fetch.

Start it

Terminal 
git clone https://github.com/axeltoll/recipe-bank.git
cd recipe-bank
npm start

The dashboard opens at http://127.0.0.1:4780. Set the PORT and HOST environment variables to change the address. npm run dev does the same and restarts when the server or the shared library changes.

By default the server listens on 127.0.0.1, so only your own machine can reach it. The server has no login. If you set HOST to an address other devices can reach, anyone on that network can add to the queue and remove from it, so keep it on a network you trust.

Where your data lives

PathWhat it holds
recipes/<id>.jsonOne file per recipe. This is the data. The file name equals the recipe's id.
data/queue.jsonVideos waiting for analysis.
Your browserOnly conveniences: the filters you last used and the ingredients you ticked.

There is no database. Back up the two paths above and you have backed up everything.

Add a video

Press Add video on the dashboard and paste a link to a YouTube video or Short, a TikTok or an Instagram Reel. The video joins the queue. If it is already a recipe or already queued, the dashboard tells you instead of adding it twice.

Write the recipe

A recipe is one JSON file in recipes/. The format is documented in CLAUDE.md and enforced by lib/recipe.mjs. Today you write that file yourself, or you ask a coding agent that reads CLAUDE.md to write it from the video. The packaged Recipe Agent that does this from a link is planned, not shipped.

The rules that matter more than the format:

  1. Never invent an amount. An amount is the creator's own words. If the video does not say, the amount is empty and its basis is unstated.
  2. Steps come from the video. If part of the method is missing, mark the recipe partial and list what is missing under gaps.
  3. Give every ingredient a short filter key, lowercase and singular, and reuse the keys that already exist.
  4. Add a timestamp in seconds to each step where you can. The dashboard turns it into a play from here button.
  5. Keep transcripts, captions and frames out of the repository. They are the creators' own content.

When the recipe file exists, remove the matching entry from data/queue.json. The dashboard already hides queue entries whose video is in recipes/. You are responsible for following each platform's terms when you capture a video.

Check your files

CommandWhat it does
npm run validateChecks every recipe file and the queue against the contract. Run it before you commit.
npm testRuns the tests on Node's built-in test runner.

Host a read-only copy

npm run build writes a static copy of the dashboard to dist/. Any static host can serve it. The copy is read-only: it cannot change the queue, so Add video copies a request message instead of queueing.

The repository also has npm run deploy, which builds and then publishes dist/ to a Cloudflare Pages project with wrangler. It needs your own Cloudflare account and project.

What is planned

These are on the roadmap and not in the repository yet:

  • A Recipe Agent definition with entry files for common coding agents, and the video analysis packaged as a reusable skill.
  • A self-hosting document in the repository and a setup check for the optional tools the agent needs, such as ffmpeg, yt-dlp, a local speech-to-text engine and tesseract. The dashboard keeps working without any of them.
  • A form to add and edit recipes in the dashboard, and queueing from the static copy.
