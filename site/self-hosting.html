What you need

  • Node.js 22 or newer.
  • Git, to clone the repository.
  • A current browser.

There is no install step and no build step for local use. Recipe Bank has no dependencies, so there is nothing for npm install to fetch.

Start it

Terminal 
git clone https://github.com/axeltoll/recipe-bank.git
cd recipe-bank
npm start

The dashboard opens at http://127.0.0.1:4780. Set the PORT and HOST environment variables to change the address. npm run dev does the same and restarts when the server or the shared library changes.

By default the server listens on 127.0.0.1, so only your own machine can reach it. Changes (adding to the queue, removing from it, saving a recipe, importing a pack) are accepted only when the request is addressed to a loopback name such as 127.0.0.1 from your own machine, to the exact address in HOST, or to a name listed in RECIPE_BANK_HOSTS (comma-separated, such as kitchen.lan).

To use the dashboard from other devices, set HOST to the address they will open, such as 192.168.1.20, or list the names they use in RECIPE_BANK_HOSTS. HOST=0.0.0.0 or HOST=:: listens on every interface but allows no name by itself: other devices can open the dashboard, and Add video, removing from the queue and every other change fail with a 403 until their name is in RECIPE_BANK_HOSTS. A loopback name only counts for requests from your own machine.

The server has no login. Anyone who can reach it under an allowed name can add to the queue and remove from it, so keep it on a network you trust.

Where your data lives

PathWhat it holds
recipes/<id>.jsonOne file per recipe. This is the data. The file name equals the recipe's id.
data/queue.jsonVideos waiting for analysis.
Your browserWhat you set in the dashboard: the theme, the filters you last used, ticked ingredients and shopping items, the week plan, the pantry, the household profile and the food budget. It stays in that browser and is in no file.

The two paths are inside the repository unless you set RECIPE_BANK_DIR to another folder holding recipes/ and data/. Then that folder is your bank: the server, npm run validate and the queue helper read and write it, not the repository.

There is no database. Back up recipes/ and data/queue.json in the folder your bank is in and you have backed up every file Recipe Bank writes. What a browser keeps is not in those files.

Check your files

CommandWhat it does
npm run validateChecks every recipe file and the queue against the contract. Run it before you commit.
npm testRuns the tests on Node's built-in test runner.

Host a read-only copy

npm run build writes a static copy of the dashboard to dist/. Any static host can serve it. The copy is read-only: it cannot change the queue, so Add video copies a request message instead of queueing.

The repository also has npm run deploy, which builds and then publishes dist/ to a Cloudflare Pages project with wrangler. It needs your own Cloudflare account and project.

Both always use the recipes and the queue in the repository. They ignore RECIPE_BANK_DIR, so a bank kept in another folder is never published by accident.

Optional capture tools

Being merged This is built and is being merged into the main branch. Until the merge lands, a fresh clone may not have it.

The note above covers the rest of this page: the setup check, the capture helper and the capture store that the Recipe Agent uses. The dashboard and the validator work with Node alone.

npm run doctor reports which tools it finds on your PATH, with install hints. A missing capture tool is information, not an error. The check does not run the tools, does not use the network and does not fetch models.

ToolUsed for
yt-dlpCaptions, the description, metadata, and the audio or video file when one is needed.
ffmpegAudio conversion and sampled frames.
whisper-ctranslate2 or whisperLocal speech-to-text, when the captions have no usable text.
tesseractReading English text that is shown on screen.

Installing the tools and getting a speech-to-text model are your own steps. Transcription needs a model that is already on your disk: set RECIPE_BANK_STT_MODEL to its absolute path. The helper never names a model in a way that would start a download, and it runs transcription on the CPU.

Where captures are kept

Captured material is the creators' own content, so the capture helper keeps it outside the repository. Set RECIPE_BANK_CAPTURE_DIR to an absolute folder of your choice, or let the helper use the data folder of your system:

SystemCapture folder
Linux$XDG_DATA_HOME/recipe-bank/captures, or $HOME/.local/share/recipe-bank/captures
macOS$HOME/Library/Application Support/recipe-bank/captures
Windows%LOCALAPPDATA%\recipe-bank\captures
  • Each video gets its own folder, named after the platform and the video id.
  • A folder inside the repository, one of its worktrees, or a symlink that leads back into one is refused.
  • A capture can hold captions, the description, metadata, audio, video, a transcript, frames, text read from frames, tool logs and a report of each step. Do not publish these, and do not put them in commits, issues or support messages.
  • Managing access, backups, disk space and deletion is up to you. Delete a video's capture folder when you no longer need it.
  • You are responsible for following each platform's terms and for having permission to capture the material. Do not get around logins, paywalls or other access restrictions.

Troubleshooting

What you seeWhat to do
A tool is reported missingRun npm run doctor again in the terminal the agent uses. Restart the terminal after changing PATH. Without yt-dlp the capture helper stops; the dashboard still runs.
No speech-to-textCheck the name of the program and the path in RECIPE_BANK_STT_MODEL. Analysis from captions alone is still possible.
No captions, or access deniedRead the capture report and the tool logs in the capture folder. Record the limit as a gap. Do not guess a recipe from a title.
Text on screen is read badlyThe helper reads English. Look at the frames yourself for other languages or handwriting.
The capture folder is refusedUse an absolute folder outside every checkout of the repository.
The queue looks staleStop the dashboard before the queue helper runs, and start it again afterwards.
Validation failsFollow the messages from npm run validate. A missing fact becomes an unstated amount or a gap, never a guess.
